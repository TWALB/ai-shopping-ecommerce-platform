## 1. 版本与验证证据

A1 用到的两个 BCrypt 密文**不是手写或猜测的**，而是用项目实际锁定的 jar 编译运行生成并自验的。手写错误哈希会精确复现我们正在修的 bug（错的哈希与中文占位符表现完全一致：静默失败、只提示"用户名或密码错误"）。

| 项 | 值 |
|---|---|
| 验证用 jar | `spring-security-crypto-6.2.4.jar`（Spring Boot 3.2.5 解析出的版本，取自 `~/.m2`）+ `spring-jcl-6.1.6.jar` |
| 验证方式 | `BCryptPasswordEncoder.encode(raw)` 生成 → `matches(raw, hash)` 回验 |

实测结果：

| 断言 | 结果 |
|---|---|
| `admin123` 密文长度 | 60 字符（`VARCHAR(100)` 装得下） |
| `matches("admin123", admin 密文)` | **true** |
| `matches("admin124", admin 密文)` | false |
| `matches("merchant123", merchant 密文)` | **true** |
| `matches("merchant124", merchant 密文)` | false |
| `matches(任意, "此处替换为BCrypt密文")` | **false 且不抛异常**，日志输出 `警告: Encoded password does not look like BCrypt` |

## A1-3 新增启动自检（推荐，从根上消灭这类静默失败）

**为什么加这个**：即使操作者忘了替换占位符，也不会卡在"密码错误"这种毫无线索的现象上——自检会把密码重置并打出醒目告警。这是对"这一类 bug"的免疫，而不只是修当前两个字符串。

新建文件：`code/backend/src/main/java/com/digitalmall/config/SeedPasswordInitializer.java`

```java
package com.digitalmall.config;

import com.baomidou.mybatisplus.core.toolkit.Wrappers;
import com.digitalmall.entity.SysUser;
import com.digitalmall.mapper.SysUserMapper;
import lombok.RequiredArgsConstructor;
import lombok.extern.slf4j.Slf4j;
import org.springframework.boot.ApplicationArguments;
import org.springframework.boot.ApplicationRunner;
import org.springframework.security.crypto.bcrypt.BCryptPasswordEncoder;
import org.springframework.stereotype.Component;

import java.util.List;
import java.util.Map;

/**
 * 启动自检：修复「种子账号密码为 SQL 占位符」导致的静默登录失败。
 *
 * 背景：BCryptPasswordEncoder.matches() 对非法密文格式返回 false 而非抛异常
 * （只打一条 warning），因此占位符未替换时，现象只是"用户名或密码错误"，
 * 排查成本极高，且会连锁导致：admin 登不进 → 商家入驻无法审核 → 商家端全线 403。
 *
 * 行为：仅对下面列出的演示账号生效；若密码不是 BCrypt 格式则重置并告警。
 *      其他账号一律只告警、不修改。
 *
 * ⚠️ 生产环境应删除本类，或加 @Profile("!prod") 限制生效环境。
 */
@Slf4j
@Component
@RequiredArgsConstructor
public class SeedPasswordInitializer implements ApplicationRunner {

    /** 演示账号 → 约定明文口令（仅用于修复占位符，非生产用途） */
    private static final Map<String, String> DEMO_ACCOUNTS = Map.of(
            "admin", "admin123",
            "merchant1", "merchant123"
    );

    private final SysUserMapper sysUserMapper;
    private final BCryptPasswordEncoder encoder = new BCryptPasswordEncoder();

    @Override
    public void run(ApplicationArguments args) {
        List<SysUser> seeds = sysUserMapper.selectList(Wrappers.<SysUser>lambdaQuery()
                .in(SysUser::getUsername, DEMO_ACCOUNTS.keySet()));
        if (seeds.isEmpty()) {
            log.warn("【启动自检】未找到种子账号 admin / merchant1，请确认已执行建表 SQL 与 测试商品数据.sql");
            return;
        }

        int fixed = 0;
        for (SysUser user : seeds) {
            if (isBcrypt(user.getPassword())) {
                continue;
            }
            String raw = DEMO_ACCOUNTS.get(user.getUsername());
            user.setPassword(encoder.encode(raw));
            sysUserMapper.updateById(user);
            fixed++;
            log.warn("【启动自检】账号 {} 的密码不是 BCrypt 密文（多为 SQL 占位符未替换），"
                    + "已自动重置为 {}，请登录后立即修改", user.getUsername(), raw);
        }
        if (fixed > 0) {
            log.warn("==================================================================");
            log.warn("【启动自检】共修复 {} 个种子账号密码。如为首次启动，请忽略本告警。", fixed);
            log.warn("==================================================================");
        }

        // 其他账号：非 BCrypt 格式只告警，不擅自修改
        Long abnormal = sysUserMapper.selectCount(Wrappers.<SysUser>lambdaQuery()
                .notIn(SysUser::getUsername, DEMO_ACCOUNTS.keySet())
                .and(w -> w.isNotNull(SysUser::getPassword).ne(SysUser::getPassword, ""))
                .notLikeRight(SysUser::getPassword, "$2a$")
                .notLikeRight(SysUser::getPassword, "$2b$")
                .notLikeRight(SysUser::getPassword, "$2y$"));
        if (abnormal != null && abnormal > 0) {
            log.warn("【启动自检】检测到 {} 个非种子账号的密码不是 BCrypt 密文，请人工核查（未自动修改）", abnormal);
        }
    }

    private boolean isBcrypt(String password) {
        return password != null
                && (password.startsWith("$2a$") || password.startsWith("$2b$") || password.startsWith("$2y$"));
    }
}
```

## A1-4 ⚠️ 警示：不要"顺手优化"成 `BCrypt.checkpw()`

这是本次修复中最容易被好心改坏的一点：

| 调用方式 | 传入非法密文（如中文占位符）时的行为 |
|---|---|
| `BCryptPasswordEncoder.matches()`（**项目现用**） | 内部有 `BCRYPT_PATTERN` 正则守卫 → 打 warning + **返回 false** |
| `BCrypt.checkpw()`（直接调 BCrypt 类） | **抛 `IllegalArgumentException: Invalid salt`** → 被兜底 `@ExceptionHandler(Exception.class)` 转成 **500 服务器异常** |

已在项目同版本 jar 实测确认。改动 `AuthServiceImpl` 时**不要**把 `passwordEncoder.matches(...)` 换成 `BCrypt.checkpw(...)`，否则"静默失败"会升级成"每次登录 500"。

### ⚠️ 关于「给 `@RequestParam` 加 `@Min`」的坑（建议改为服务层校验）

网上常见写法是给 Controller 加 `@Validated` + `@RequestParam @Min(1)`。**在本项目上不要这么做**，原因：

- 本项目用 Spring Boot 3.2.5（Spring Framework 6.1），Controller 方法参数的约束校验会抛 `HandlerMethodValidationException` / `ConstraintViolationException`；
- 而 `GlobalExceptionHandler` 里有一个兜底的 `@ExceptionHandler(Exception.class)`，它会把这两类异常吞掉并返回 **`code=500`**，而不是 400。

如果确实想用注解式校验，必须同时在 `GlobalExceptionHandler` 补一个处理器：

```java
@ExceptionHandler({jakarta.validation.ConstraintViolationException.class,
                   org.springframework.web.method.annotation.HandlerMethodValidationException.class})
public Result<Void> handleConstraint(Exception e) {
    return Result.error(400, "参数不合法");
}
```

**更省事的做法**：按本文件 A4-6 直接在 Service 层判空与范围，绕开这个坑。

## A4-7 存量脏数据修复 SQL（必做）

代码修好后，**已经产生的脏数据仍会流过去**（历史 `quantity < 1` 的购物车行、`stock IS NULL` 的 SKU 正是此前 bug 造成的）。执行：

```sql
-- 1) 购物车里的非法数量归一到 1
UPDATE cart SET quantity = 1 WHERE quantity < 1 OR quantity > 999;

-- 2) null / 负库存归零（null 会让 stock >= ? 恒假，表现为永久"库存不足"）
UPDATE product_sku SET stock = 0 WHERE stock IS NULL;
UPDATE product_sku SET stock = 0 WHERE stock < 0;

-- 3) 已产生的负金额订单：人工核查后再处理（不要直接改，先看有多少）
SELECT id, order_no, user_id, total_amount, pay_amount, status, created_time
FROM `order` WHERE pay_amount <= 0 OR total_amount <= 0;
```

第 3 条查出来的订单如果 `status=0`（待付款）建议直接置为已取消（`status=4`）并把库存回补；若已支付，需人工评估（模拟支付下无真实资损）。
